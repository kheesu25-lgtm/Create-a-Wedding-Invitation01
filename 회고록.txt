잘한 점

GitHub으로 팀원들과 처음 공동 작업을 해보며 브랜치, 커밋, Pull Request의 전체 흐름을 직접 경험했다.

아쉬운 점

각자 브랜치를 만들고 Pull Request(PR)를 올리는 과정을 제대로 진행하지 못했다. 브랜치를 나누는 이유와 PR로 병합하는 절차를 충분히 이해하지 못한 채 작업한 것 같다.
내 작업에만 집중하느라 다른 팀원의 코드를 리뷰하거나 고쳐보려는 노력을 하지 못했다. 협업의 핵심인 코드 리뷰와 피드백을 놓쳤다.

다음에 시도할 점

작업 전에 브랜치 생성 → 커밋 → PR → 리뷰 → 병합 순서를 팀원과 함께 정리하고 시작하기
다른 사람의 PR에 최소 한 번은 리뷰나 코멘트 남기기
모르는 부분은 혼자 넘기지 말고 팀원에게 바로 질문하기
